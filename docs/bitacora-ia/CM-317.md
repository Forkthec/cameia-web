## Tarea 1 · 23-oct-2026 · Herramienta: Claude Code (Claude Opus 5.5) · Prueba de Silero VAD en el navegador con pnpm dev (tarea 1 del Anexo A del SPEC, ADR 0009)
Petición/prompt relevante (resumen). Verificar lo que el ADR 0009 dejó sin comprobar: si `?url` llega a `onnxruntime-web/dist/…`, si `pnpm dev` sirve el modelo, el worklet, el `.wasm` y el `.mjs`, y si MicVAD carga y cuenta tramos en un navegador real. Con el menor código posible y sin dejar nada temporal en el repositorio.

Resultado. La prueba se hizo en un `git worktree` fuera del repositorio (`--detach` en `25dcfb6`, `pnpm install --frozen-lockfile --offline`), con una página `vad-probe.html`, `src/vadProbe.ts` y un módulo por cada forma de importar los assets. MicVAD se creó con las opciones de §7 del SPEC (`model: 'v5'`, `startOnLoad: false`, `getStream` con el stream de `getUserMedia({ audio: true })`, `pauseStream` vacío, tramo con voz si `isSpeech` ≥ 0,3, `baseAssetPath` y `onnxWASMBasePath` derivados de las URLs `?url`) y escuchó 5 s. El autor probó en los tres navegadores:

| Navegador (Windows) | `MicVAD.new` | Tramos con voz, hablando | Tramos con voz, en silencio |
| --- | --- | --- | --- |
| Chrome 155 | 331 ms | 101 | 42 (hubo algún sonido; se revisa en la tarea 10) |
| Edge 155 | 502 ms | 87 | 0 |
| Firefox 158 | 405 ms | 73 | 3 |

En los tres: `onnxruntime-web/dist/…?url` no resuelve («is not exported under the conditions…», el `exports` del paquete solo expone `.`, `./all`, `./wasm`, `./webgl` y `./webgpu`); la ruta relativa `../../node_modules/onnxruntime-web/dist/…?url` sí. `@ricky0123/vad-web/dist/…?url` resuelve por el paquete. Vite sirve los cuatro archivos desde `/node_modules/.pnpm/…/dist/`, el `.wasm` con `application/wasm`, y el navegador pide los cuatro (el worklet se ve en la lista de recursos de Firefox). Con más de 62 tramos hablando, los tres superan el mínimo de HU-5.8.

Qué se aceptó, corrigió o rechazó, y por qué.

Cada forma de importar fue a su propio módulo: si un import `?url` no resuelve, Vite rechaza el módulo entero, y así la página podía mostrar cuál falló y el motivo.
El aviso «Failed to run dependency scan» de Vite lo causó el import que fallaba a propósito (Vite revisa todos los `.html` de la raíz); no es un problema de la aplicación.
El ADR 0009 se corrigió en la misma rama, antes de fusionar: es una corrección de forma (ruta relativa para ORT), no un cambio de decisión. Siguen sin comprobar `vite build` y `vite preview` con el módulo real (tarea 9) y la caché de Firebase Hosting.
Claude Code avisó que había detenido el servidor de desarrollo por falta de memoria, pero al cerrar la prueba el proceso de Vite del worktree seguía escuchando en el puerto 5173. Al terminar se detuvo ese proceso, se borró el worktree (`git worktree remove --force` falló por rutas largas de Windows y la carpeta se borró con `rm -rf`) y se corrió `git worktree prune`; el repositorio principal quedó con `git status` vacío.
