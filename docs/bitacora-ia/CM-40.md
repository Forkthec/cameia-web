## Tarea 2 · 17-sep-2026 · Herramienta: Claude Code (Claude Sonnet 5) · Correcciones visuales tras prueba manual del usuario

**Petición/prompt relevante (resumen).** El usuario probó `/ingresar` en su propio navegador (esta
sesión sigue sin poder hacerlo) y reportó tres cosas en un mismo mensaje: (1) al pasar el mouse
sobre el botón de mostrar/ocultar contraseña, el resaltado de `hover` se veía grande, tapaba el
borde del campo, y el ícono no se veía centrado dentro de ese resaltado; (2) había ajustado a mano
`cursor-pointer` en el botón "Ingresar" (le faltaba) y pidió confirmación más generalizarlo a todos
los botones; (3) pidió un plan (sin tocar archivos) para conectar el frontend a Firebase con
credenciales reales que ya tenía. Más adelante, en la misma sesión, el usuario pegó **la clave
privada del Admin SDK de Firebase** (`cameia-2d8b5-firebase-adminsdk-...json`) creyendo que no era
sensible.

**Resultado.**

- **Hallazgo de seguridad comunicado, no ignorado (`CONTRIBUTING.md` §Documentación y seguridad):**
  se le explicó al usuario que el JSON pegado es una credencial real de servidor (acceso total,
  bypassa reglas de seguridad), distinta de la config web pública que sí usa el frontend, y se le
  recomendó revocarla/rotarla en el Firebase Console. No se usó ni se guardó en ningún archivo del
  repositorio.
- `design-system/atoms/Button/Button.tsx`: se agregó `cursor-pointer` a la base de `buttonVariants`
  (todo botón que use este átomo lo hereda; `disabled:cursor-not-allowed` lo sigue ganando por
  especificidad). Se quitó el `cursor-pointer` que el usuario había puesto suelto en
  `LoginForm.tsx` (ya redundante; además solo cubría una de las dos variantes condicionales del
  botón "Ingresar", no la de `loading`).
- `design-system/molecules/PasswordField/PasswordField.tsx`: el botón del ojo (`variant="icon"`,
  círculo de 44×44 por defecto) ocupa el borde derecho completo del campo (misma altura que
  `Input`); un círculo de 44px no calza con el radio de 10px del campo y tapaba su esquina. Se
  sobreescribió a `rounded-r-md rounded-l-none` para que el fondo de `hover` calce con la forma del
  campo en vez de una circunferencia suelta.
- Plan para conectar Firebase (sin tocar archivos, como se pidió): distinguir la config web pública
  (4 valores, se sacan de Firebase Console → Configuración del proyecto → "Tus apps") de la clave
  de Admin SDK (no la usa el frontend); dónde ponerlos (`.env` local, ya en `.gitignore`, no
  `.env.example`); habilitar el método de acceso "Correo/contraseña" en Authentication; crear un
  usuario de prueba a mano (Registro/`CM-34` sigue siendo un placeholder, no hay alta desde la app
  todavía); se verificó en el código (no se asumió) que `VITE_ENABLE_MSW` no interfiere porque
  `main.tsx` nunca llama a `worker.start()` todavía.
- El usuario resolvió la conexión a Firebase por su cuenta: hacía falta reiniciar `pnpm dev` tras
  editar `.env` (Vite solo lee variables de entorno al arrancar).
- **Pendiente, no resuelto:** el usuario probó el cambio de `PasswordField` y reportó que "aún se ve
  mal". Se le pidió una captura para no seguir corrigiendo a ciegas; la captura mostró el campo en
  estado de error (borde rojo, posiblemente tras un intento de login fallido) con un fondo
  celeste/lavanda que no corresponde a ningún estilo propio de `Input` (probable autocompletado del
  navegador, fuera del control de este código) y el botón del ojo con una forma distinta a la del
  resto del campo — no quedó claro si la captura correspondía al estado de `hover` pedido o al
  estado de reposo, ni si el fondo celeste era parte de la queja. Se le devolvieron las dos
  preguntas puntuales; **la sesión terminó sin que el usuario las respondiera y sin un segundo
